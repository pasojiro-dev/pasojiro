# 全国の店を増やす作業の手順書(自動実行用)

パソ二郎(https://pasojiro-dev.github.io/pasojiro/ 。GitHub Pages で公開。2026-10-24 に Netlify の無料枠が尽きたため移行)の `shops.json` に、全国の二郎系の店を、1回の実行で1都道府県ずつ足していく。
判断の基準は、公開している `criteria.html`(掲載の基準)。この手順書は、その運用の手順。

## 絶対に守ること
- 触ってよいのは `shops.json` と、この手順書の「進み具合」だけ。`index.html` などのコードは変えない。
- 出典として書くのは、**実際に開いて内容を読んだページだけ**。読んでいないURLを `src` に入れない。
- 口コミや記事の文章を、そのまま写さない。事実(住所、麺、トッピング、営業時間など)を短くまとめる。
- 店主の名前など、個人名は書かない。コミットの作者は設定済み(`pasojiro-dev` と匿名メール)。本名やメールを使わない。
- 迷う店は、**載せない**。「載せなかった理由」を進み具合に残す。
- 検証(`python tools/validate.py`)が通らないものは、push しない。

## 1回の実行の手順
0. 実行環境について(PCでも、クラウドでも、この手順書で動く)
   - 作業場所は、リポジトリのルート(`shops.json` があるフォルダ)。PCの `C:\Users\tk\pasojiro` でも、クラウドの取得済みフォルダでも、そこへ移動してから始める。
   - コマンドは、シェル(bash)で実行する。`python` がなければ `python3` を使う。どちらもなければ、座標取得と検証ができないので、店を足さずに終了して、その旨を報告する。
   - コミットの作者を、毎回、次のとおり設定する(本名やメールアドレスを使わない)。
     `git config user.name "pasojiro-dev"` と `git config user.email "258582869+pasojiro-dev@users.noreply.github.com"`
   - **main ブランチに push する**。もし main に push できない(別のブランチにしか push できない)ときは、別ブランチを作って push せず、変更を捨てて終了し、「mainに push できなかった」と報告する。
   - 外部サイト(地理院の住所検索、食べログなど)に接続できないときは、無理に続けず、できなかった内容を報告して終了する。
1. `git pull --rebase origin main` で最新にする。作業前に `git status` がきれいなことを確認する。
2. 下の「進み具合」から、状況が **「未」** の都道府県を、上から1つ選ぶ。「手動作業中」「途中」「済」の県は選ばない(運営者や手動の作業と、かち合わないようにするため)。
3. その地域の二郎系を紹介する記事・まとめを、検索で複数見つける(食べログのまとめ、ラーメンデータベース、地域メディアなど)。2本以上を `WebFetch` で読み、店名・住所・特徴・閉店の注記を取り出す。
4. 候補の店ごとに、基準を当てる。
   - 実在・営業中: 住所が分かり、閉店・休業の注記がない。
   - 出典が2つ以上(読んだページが2つ以上で、その店が二郎系・二郎インスパイアとして載っている)。公式サイトが「二郎系」と名乗っていれば出典1つに数えてよい。
   - **食べログの個別店ページも、出典1つに数えてよい**(方針変更・2026-10-24)。ただし、実際に開いて、(a) 住所と営業状況(閉店表示がない)が読めること、(b) 店の紹介文・ジャンル・口コミの記述に、二郎系・インスパイアであることや、7つの特徴が書かれていることが読み取れること、の両方を満たすときだけ。住所があるだけのページは数えない。もう1つは、記事・まとめ・公式サイトなど、食べログの店ページ以外のページにする(食べログの店ページ2つや、同じ店の別の食べログページを2つに数えない)。
   - 記事が東京など別の地域のまとめだったときは、対象の地域の店が載っていないので、出典に数えない(読んだページの主題を必ず確認する)。
   - 7つの特徴のうち、3つ以上が、読んだ文章から確認できる(`太麺`,`野菜増し`,`ニンニク`,`アブラ`,`塊の豚`,`濃いスープ`,`量が多い`)。
   - **系列店・グループ店は載せてよい**(運営者の判断・2026-10-24)。「夢を語れ」「限界を超えろ」「踊ろうサンダーバード」など、二郎系の看板で複数店を出すグループも、ほかの基準(出典2つ以上・特徴3つ以上・営業の確認)を満たせば載せる。二郎系ではない一般の全国チェーンは載せない。
   - 直系店(ラーメン二郎の看板)は、すでに全部入っている。足さない。
   - 元ラーメン二郎の店主・従業員が独立した店(独立系)は、その事実を示す出典があるときだけ、`kind` を `dokuritsu` にして足す。
5. 営業時間・定休日は、読んだページに書いてあれば `sched` と `closed` に入れる。書いていなければ `sched` を `[{"d":"月〜日","t":null}]`、`closed` を `"不明"`、`hnote` を `"営業時間は公式Xで確認してください"` にする。
6. 1回の実行で足す店は、**多くても100軒**(運営者の決定・2026-10-24。以前は25軒)。候補が多い都道府県は、次回に続きを行う(進み具合に「途中」と書く)。100軒に近いときは、座標取得(`geocode.py`)と検証(`validate.py`)を先に通してから push する。途中で止まっても壊れたデータを push しない。
7. `shops.json` に店を足す。座標は、`lat` と `lng` を `null` にして、`python tools/geocode.py` を実行して取る。
   - 結果が「番地まで特定できず」(町名や市町村の中心点)のときは、その店の食べログのページに地図の座標があれば、それを使う(`center=緯度,経度` が HTML に入っている)。なければ、その店は載せない。
8. `python tools/validate.py` を実行し、エラー0件にする。
9. コミットして push する。メッセージ例: 「北海道の二郎インスパイアN軒を追加(出典2つ以上・特徴3つ以上)」。コミットメッセージの末尾に、決められた Co-Authored-By の行を付ける。
10. 公開サイトに反映されたか確認する(`https://pasojiro-dev.github.io/pasojiro/shops.json` の件数)。反映が遅いときは、数分おいて再確認する。数分で反映されなくても、慌てて何度も push しない。
11. この手順書の「進み具合」を更新して、もう一度コミット・push する。

## 店のデータの形(1軒の例)
```json
{
  "id": "hananona",
  "name": "麺屋 花の名",
  "group": "二郎インスパイア",
  "area": "佐久市",
  "addr": "長野県佐久市猿久保667-5",
  "tel": "",
  "lat": null, "lng": null, "pos": "town",
  "jiro": 4,
  "memo": "(事実を短く。口コミの文章は写さない)",
  "kind": "inspire",
  "feat": ["太麺", "野菜増し", "ニンニク", "アブラ", "塊の豚", "濃いスープ", "量が多い"],
  "src": [{"t": "出典の名前", "u": "https://..."}, {"t": "出典の名前", "u": "https://..."}],
  "closed": "水",
  "sched": [{"d": "月火木金土日祝", "t": ["11:30-14:00", "18:00-21:00"]}, {"d": "水", "t": []}],
  "hnote": "任意の補足"
}
```
- `id`: 半角小文字・数字・ハイフン、40字まで。ほかの店と重ならないこと(投稿機能の店の識別にも使う)。
- `jiro`(二郎度): 特徴が3つ→2、4〜5つ→3、6〜7つ→4。直系だけが5。
- `sched` の `d`: 曜日は `月火水木金土日` と `祝`、範囲は `月〜金`。`t` は `["HH:MM-HH:MM", ...]`、休みは `[]`、不明は `null`。深夜は `26:30` のように24時を超えて書く。全曜日(日〜土)を、どれかの行が覆うこと。
- 例外で載せる店は `exception` に理由を書く(運営者が決めた場合だけ。自動実行では使わない)。
