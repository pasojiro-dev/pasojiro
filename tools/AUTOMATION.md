# 全国の店の更新作業の手順書(自動実行用)

パソ二郎(https://pasojiro-dev.github.io/pasojiro/ 。GitHub Pages で公開)の `shops.json` を、**最新に保つ**ための手順。
全国47都道府県の追加調査は 2026-10-25 に一巡した(記録は `tools/AUTOMATION_HISTORY.md`)。今後は、1回の実行で **地域を1つ** 選び、次の3つを点検する。

1. 閉店チェック: 掲載中の店が閉店・移転していないか
2. 営業時間チェック: 営業時間・定休日が変わっていないか
3. 新店チェック: 新しくできた二郎系の店はないか

判断の基準は、公開している `criteria.html`(掲載の基準)。

## 絶対に守ること
- 触ってよいのは `shops.json` と、この手順書の「進み具合」だけ。`index.html` などのコードは変えない。
- 出典として書くのは、**実際に開いて内容を読んだページだけ**。読んでいないURLを `src` に入れない。
- 口コミや記事の文章を、そのまま写さない。事実(住所、麺、トッピング、営業時間など)を短くまとめる。
- 店主の名前など、個人名は書かない。コミットの作者は設定済み(`pasojiro-dev` と匿名メール)。本名やメールを使わない。
- 迷う店は、**載せない**。「載せなかった理由」を点検の記録に残す。
- 検証(`python3 tools/validate.py`)が通らないものは、push しない。

- 閉店の判断は、**食べログの店ページの「閉店」表示、公式の告知、ニュースのどれかを実際に読んだとき**だけ。「見つからない」「情報が古い」だけでは外さない。

## 1回の実行の手順
0. 実行環境について(PCでも、クラウドでも、この手順書で動く)
   - 作業場所は、リポジトリのルート(`shops.json` があるフォルダ)。
   - コマンドは bash で実行する。`python` がなければ `python3` を使う。どちらもなければ、点検できないので、その旨を報告して終了する。
   - コミットの作者を、毎回、次のとおり設定する(本名やメールアドレスを使わない)。
     `git config user.name "pasojiro-dev"` と `git config user.email "258582869+pasojiro-dev@users.noreply.github.com"`
   - **main ブランチに push する**。push できないときは、別ブランチを作らず、変更を捨てて終了し、「mainに push できなかった」と報告する。
   - 外部サイトに接続できないときは、無理に続けず、できなかった内容を報告して終了する。
1. `git pull --rebase origin main` で最新にする。`git status` がきれいなことを確認する。
2. 下の「点検の進み具合」から、**最終点検日が最も古い地域**を1つ選ぶ(同じ日なら上から)。「作業中」の地域は選ばない。選んだら、すぐ「作業中(日付)」と書いてコミット・push する(運営者の手作業や次の実行とかち合わないため)。
3. **閉店・営業時間チェック**:
   - `python3 tools/check_shops.py --region <地域> --limit 80` を実行する(地域内の店が80軒より多いときは `--offset 80` などで続ける。地域内の全部の店を点検してから終わる)。食べログの店ページを1軒ずつ開くので、時間がかかる。
   - 「閉店」と出た店: 内容を確認してから、`--apply` を付けて再実行するか、`shops.json` から手で外す。外した店は「点検の記録」に店名と理由を残す。
   - 「掲載保留」と出た店(閉店・移転の可能性がある): すぐには外さない。公式サイト・SNS・ニュースを `WebSearch` で調べ、閉店・移転が確認できたら外す。確認できなければ残し、「点検の記録」の「要再確認」に書く。**2回続けて掲載保留なら外す**。
   - 「営業時間差」と出た店: 食べログの営業時間が最新とは限らない。直近の口コミがある(直近12か月)ときだけ `--apply` で反映する。休業中の告知があれば `hnote` に書く。
   - 「食べログURLなし」の店: `WebSearch`(`tabelog.com` で店名を検索)で店ページを探し、閉店表示を確認する。見つかったURLは `src` に足さない(読んで基準を満たすと確認したときだけ足す)。
4. **新店チェック**:
   - 「<地域> 二郎系 新店 オープン 2026」「<地域> 二郎インスパイア 新規開店」などで、直近1年以内にできた店・まだ載せていない店を探す。地域の二郎系まとめ記事(TSグルメ、SUSURU WEB など)も、新しい店が増えていないか読む。
   - `tools/AUTOMATION_HISTORY.md` に「見送り」と書いた店は、見送り理由が解消しているときだけ再検討する(例: 新しい口コミが出た、別の記事が出た)。
   - 系列店(ラーメン豚山、夢を語れ系、立川マシマシ、麺でる、ラーメン富士丸など)の**新規出店**も探す。公式サイトの新店のお知らせを読む。
5. 候補の店ごとに、基準を当てる。
   - 実在・営業中: 住所が分かり、閉店・休業の注記がない。
   - 出典が2つ以上(読んだページが2つ以上で、その店が二郎系・二郎インスパイアとして載っている)。公式サイトが「二郎系」と名乗っていれば出典1つに数えてよい。
   - **食べログの個別店ページも、出典1つに数えてよい**(方針変更・2026-10-24)。ただし、実際に開いて、(a) 住所と営業状況(閉店表示がない)が読めること、(b) 店の紹介文・ジャンル・口コミの記述に、二郎系・インスパイアであることや、7つの特徴が書かれていることが読み取れること、の両方を満たすときだけ。住所があるだけのページは数えない。もう1つは、記事・まとめ・公式サイトなど、食べログの店ページ以外のページにする(食べログの店ページ2つや、同じ店の別の食べログページを2つに数えない)。
   - 記事が東京など別の地域のまとめだったときは、対象の地域の店が載っていないので、出典に数えない(読んだページの主題を必ず確認する)。
   - 7つの特徴のうち、3つ以上が、読んだ文章から確認できる(`太麺`,`野菜増し`,`ニンニク`,`アブラ`,`塊の豚`,`濃いスープ`,`量が多い`)。
   - **系列店・グループ店は載せてよい**(運営者の判断・2026-10-24)。「夢を語れ」「限界を超えろ」「踊ろうサンダーバード」など、二郎系の看板で複数店を出すグループも、ほかの基準(出典2つ以上・特徴3つ以上・営業の確認)を満たせば載せる。二郎系ではない一般の全国チェーンは載せない。
   - 直系店(ラーメン二郎の看板)は、すでに全部入っている。足さない。
   - 元ラーメン二郎の店主・従業員が独立した店(独立系)は、その事実を示す出典があるときだけ、`kind` を `dokuritsu` にして足す。
   - 営業時間・定休日は、読んだページに書いてあれば `sched` と `closed` に入れる。書いていなければ `sched` を `[{"d":"月〜日","t":null}]`、`closed` を `"不明"`、`hnote` を `"営業時間は公式Xで確認してください"` にする。
6. 1回の実行で足す店は、**多くても100軒**。
7. 店を足すときは、座標を、`lat` と `lng` を `null` にして、`python tools/geocode.py` を実行して取る。
   - 結果が「番地まで特定できず」(町名や市町村の中心点)のときは、その店の食べログのページに地図の座標があれば、それを使う(`center=緯度,経度` が HTML に入っている)。なければ、その店は載せない。
8. `python3 tools/validate.py` を実行し、エラー0件にする。エラーが残るなら、足した店を戻してから push する。
9. コミットして push する。メッセージ例: 「東北の点検: 閉店2軒を削除、営業時間3軒を更新、新店1軒を追加」。コミットメッセージの末尾に、決められた Co-Authored-By の行を付ける。
10. 公開サイトに反映されたか確認する(`https://pasojiro-dev.github.io/pasojiro/shops.json` の件数)。数分で反映されなくても、慌てて何度も push しない。
11. 「点検の進み具合」の最終点検日を今日の日付に更新し、点検の記録を書いて、もう一度コミット・push する。

## 店のデータの形(1軒の例)
```json
{
  "id": "hananona",
  "name": "麺屋 花の名",
  "group": "二郎インスパイア",
  "area": "佐久市",
  "addr": "長野県佐久市猿久保667-5",
  "tel": "",
  "lat": null, "lng": null, "pos": "town",
  "jiro": 4,
  "memo": "(事実を短く。口コミの文章は写さない)",
  "kind": "inspire",
  "feat": ["太麺", "野菜増し", "ニンニク", "アブラ", "塊の豚", "濃いスープ", "量が多い"],
  "src": [{"t": "出典の名前", "u": "https://..."}, {"t": "出典の名前", "u": "https://..."}],
  "closed": "水",
  "sched": [{"d": "月火木金土日祝", "t": ["11:30-14:00", "18:00-21:00"]}, {"d": "水", "t": []}],
  "hnote": "任意の補足"
}
```
- `id`: 半角小文字・数字・ハイフン、40字まで。ほかの店と重ならないこと(投稿機能の店の識別にも使う)。
- `jiro`(二郎度): 特徴が3つ→2、4〜5つ→3、6〜7つ→4。直系だけが5。
- `sched` の `d`: 曜日は `月火水木金土日` と `祝`、範囲は `月〜金`。`t` は `["HH:MM-HH:MM", ...]`、休みは `[]`、不明は `null`。深夜は `26:30` のように24時を超えて書く。全曜日(日〜土)を、どれかの行が覆うこと。
- 例外で載せる店は `exception` に理由を書く(運営者が決めた場合だけ。自動実行では使わない)。
