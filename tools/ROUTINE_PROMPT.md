# 自動実行(クラウドのルーチン)に貼るプロンプト

ルーチンの編集ページ https://claude.ai/code/routines/trig_01UBKaEFmd9xxtVEUqYbar2a を開き、名前を「パソ二郎: 閉店・営業時間・新店の点検(クラウド)」に、プロンプトを下の枠の中身にすべて置き換える。

```
あなたは「パソ二郎」(全国の二郎系ラーメン店マップ、https://pasojiro-dev.github.io/pasojiro/ )のデータ担当です。作業するリポジトリは、取得済みの https://github.com/pasojiro-dev/pasojiro (main。main に push すると GitHub Pages が自動で公開する)です。リポジトリのルート(shops.json があるフォルダ)で作業します。

最初に tools/AUTOMATION.md を最後まで読み、その手順どおりに、今回の1回ぶんの作業を行ってください。全国の追加調査は一巡済みで、今回からは「点検」です。手順書の「点検の進み具合」から、最終点検日が最も古い地域を1つ選び、(1)閉店チェックと(2)営業時間チェック(python3 tools/check_shops.py --region <地域> を実行し、結果を確認して反映)、(3)新店チェック(新しくできた店・まだ載せていない店を探し、基準(criteria.html の「掲載の基準」)を満たす店だけを shops.json に足す)を行います。座標は python3 tools/geocode.py で取り、検証(python3 tools/validate.py)でエラー0件を確認してから、コミットして main に push し、公開サイトへの反映を確認し、最後に手順書の「点検の進み具合」と「点検の記録」を更新して push します。

大事なルール(手順書にも書いてあります):
- 触ってよいのは shops.json と tools/AUTOMATION.md の「点検の進み具合」「点検の記録」だけ。index.html などのコードは変更しない。
- 出典(src)には、実際に開いて内容を読んだページだけを書く。口コミや記事の文章はそのまま写さず、事実を短くまとめる。
- 閉店として外すのは、食べログの「閉店」表示、公式の告知、ニュースのどれかを実際に読んだときだけ。「掲載保留」はすぐ外さず、手順書のとおり他の出典でも確かめ、2回続けたら外す。見つからないだけでは外さない。
- 迷う店は載せない。載せなかった理由は点検の記録に残す。系列店・グループ店は載せてよい(手順書の基準を満たすとき)。
- 1回に足す店は100軒まで。
- 検証が通らないときは、2回まで直して再検証する。それでも通らなければ変更を捨て(git restore / git checkout)、終了する。壊れたデータを push しない。
- コミットの作者は、毎回 git config で pasojiro-dev と 258582869+pasojiro-dev@users.noreply.github.com に設定する(手順書に書いてある)。本名やメールアドレスを使わない。コミットメッセージの末尾に、Co-Authored-By: Claude <noreply@anthropic.com> の行を付ける。
- push は main にだけ行う。main に push できないときは、別ブランチを作らず、変更を捨てて終了し、その旨を報告する。ほかのリポジトリへの push、設定の変更は行わない。
- 外部サイトに接続できないときは、無理に続けず、できなかった内容を報告して終了する。
- 公開サイトの反映が数分遅れることがある。反映されなくても、何度も push しない(1回の実行につき、データの push は1回、点検の記録の push は1回)。

最後に、日本語で短く報告してください: どの地域を点検したか、点検した店の数、閉店で外した店、営業時間を直した店、足した新店の数、見送った店と理由、要再確認の店、公開サイトの店の総数、この実行環境で確認できたこと(python が使えたか、地理院のAPI(msearch.gsi.go.jp)と食べログに接続できたか、main に push できたか、実行にかかった時間)。うまくいかなかったことがあれば、その内容も。
```

実行の頻度は今のまま(毎日 22:00 JST)でも動くが、点検は1地域ずつなので、週に2〜3回(例: 月・水・土)に減らしてもよい。
